# Achilles on Claude Code

The Claude Code adapter lives in `claude-code/` and is the only place that knows Claude Code tool names, hook events or settings files. The methodology under `skills/` is harness-neutral; this page is where its verbs map to the harness.

## Install

Achilles is a Claude Code plugin whose package root is the plugin root (`.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`).

| Path | Command | Scope |
|---|---|---|
| Marketplace | `claude plugin install achilles@achilles` | user-level; every project |
| Development checkout | `claude --plugin-dir .` from this repository | this session |
| npm dependency | `npm install @civitas-cerebrum/achilles`; the postinstall registers the plugin by merging the hook module and agents into the project's settings | this project |

Installing registers five agents (`achilles-orchestrator`, `achilles-inspector`, `achilles-author`, `achilles-reviewer`, `achilles-doc-writer`, from `agents/achilles-<role>.md`; the plugin qualifies the type further as `achilles:achilles-<role>`), the skills under `skills/`, one hook module (`claude-code/hooks.ts`, declared in `claude-code/hooks.json`), the `delegate_qa` tool, and the `/achilles` command. The browser binary is a one-shot fetch: `npx playwright-cli install-browser chromium`.

## How a QA task runs

1. The main session calls `delegate_qa` (or you type `/achilles <task>`). The adapter spawns the `achilles-orchestrator` agent with the orchestrator skill loaded and returns `RUNNING` plus a run id at once. Progress shows in the status line (the stage the run is in; the experts at work by brief name, or counted by role past two) and the Achilles pane (the stage checklist, the experts at work and since when, the last expert hand-backs), and is written to `.achilles/runs/<run-id>/progress.json`. The stages are the phases of the pipeline ledger the run writes, else the `plan` in its `resume.json`. When a stage ends and stages remain, the adapter queues a short prompt "Achilles progress (run <id>). Tell the person in a line or two…" naming what ended, what runs now and what is to go; the run's end is the hand-back's to tell.
2. The orchestrator routes the task to a workflow ([`skills/achilles-orchestrator/SKILL.md`](../../skills/achilles-orchestrator/SKILL.md) §2) and dispatches experts with the ordinary Agent tool: type `achilles-<role>` (a bare name is rewritten to the plugin's qualified one), prompt = brief path + report path, independent experts in one message, waited for in the foreground so the orchestrator keeps its context; it reads each expert's report file, not its transcript. Nesting is main → orchestrator → expert; experts dispatch nobody. An expert spawned from the main session still starts, and the spawning loop gets a note that QA work is better routed through `delegate_qa`.
3. When the orchestrator's turn completes, the adapter queues its hand-back (`DONE`, `DONE_WITH_CONCERNS`, `NEEDS_CONTEXT`, `BLOCKED`) as a prompt submission prefixed "Achilles hand-back (run <id>). Relay this to the person. If it is NEEDS_CONTEXT, ask them the numbered questions and re-delegate only with their answers.", so the main session reports it in a turn of its own without the user typing; the orchestrator skill does not repeat that framing. A `NEEDS_CONTEXT` hand-back ends with a numbered question list; answering in the chat re-dispatches the orchestrator, which resumes from `.achilles/runs/<run-id>/resume.json`, not from the conversation.

The main session is never bound by Achilles rules; only the five agents are, through their tool and path scopes.

## Agents and scopes

| Agent | Tools | Writes | Bash |
|---|---|---|---|
| `achilles-orchestrator` | Agent, Read, Glob, Grep, Write, Edit, Bash, Skill | `.achilles/**` (run dirs, briefs, resume files, the sign-off receipt), pipeline ledgers and state files under `tests/e2e/docs/**` and `tests/perf/docs/**`, `.gitignore`, `docs/evidence/<ticket>/brief.md` | `git` (worktree, merge-base, fetch, status, log, diff, add, commit; never a force push), `gh pr view\|create\|ready`, `gh issue view`, `npx playwright test`, `npx playwright-cli --version\|install-browser\|close-all\|list`, `npm run <script>`, `k6 version`, `gitleaks` |
| `achilles-inspector` | Read, Glob, Grep, Bash, Write, Edit, Skill | its report under `.achilles/runs/**`, `tests/e2e/docs/app-context.md`, spill files, `tests/e2e/inspect/**`, `tests/e2e/.auth/**`; reads the whole workspace | `npx playwright-cli -s=…`, `npx playwright test --config tests/e2e/inspect`, read-only `git status\|log\|diff\|show` |
| `achilles-author` | Read, Glob, Grep, Edit, Write, Bash, Skill | `tests/**`, `page-repository.json` and its evidence notes; scaffold briefs add `playwright*.config.*`, `package.json` scripts, `.env*`, `.gitignore`; a selector brief adds one frontend file; a mutation brief adds `.achilles/mutations.mjs` | `npx playwright test`, `npx playwright-cli -s=…`, `npx tsc --noEmit`, `npm run <script>`, `npx achilles-selector-evidence`, `npx achilles-mutate` on mutation briefs, `git status\|diff\|add`, `k6 run` on perf briefs |
| `achilles-reviewer` | Read, Glob, Grep, Bash, Write, Edit, Skill | its verdict and spill file, `docs/evidence/<change>/verify.md`, a ledger's reviewer fields | run-only: `npx playwright test`, `npx playwright-cli -s=…`, `npx tsc --noEmit`, `npm run test:unit`, `git status\|log\|diff\|show` |
| `achilles-doc-writer` | Read, Glob, Grep, Edit, Write, Bash | `docs/**` except `docs/evidence/**`, `tests/e2e/docs/**` documents (not ledgers or dot-prefixed state), `qa-summary-deck.*` and `test-catalogue.*` at the root | run-only: `node <qa-reporting script>`, `pdftoppm`, read-only `git log` |

Role scope is the enforcement for separation of duties: an author cannot approve its own work because it has no reviewer schema to return, and a reviewer cannot touch a spec. The orchestrator never writes specs and never opens a browser session; those limits are methodology ([SKILL.md](../../skills/achilles-orchestrator/SKILL.md) §1) checked by the review dispatch, not by a hook.

## Hooks (eight)

The eight hooks ship with the adapter module in 0.1.8: `claude-code/hooks.ts` registers the agents, `delegate_qa`, `/achilles` (with no task it opens the Achilles pane), the runs and the hand-back, and imports one file per hook from `claude-code/hooks/`, all on one parsed-command model (`claude-code/hooks/shell.ts`). They act on the five Achilles agents' loops only (the attribution and force-push denies cover the orchestrator too); the main session is never touched. Default posture: advise, as a note the model reads in the loop that acted; deny only the eight actions below, each irreversible or dangerous. Every hook passes everything through under `ACHILLES_DISABLE=1`. The heavy scanners run as `node` children of the hook with a timeout; one that cannot run or runs out of time lets the call through with a note.

| # | Hook | Event | Denies | Advises or rewrites |
|---|---|---|---|---|
| 1 | Bash judge (`hooks/bash-judge.ts`) | Bash tool call; Write/Edit for `secrets.none` | `git commit` with `--no-verify`, `-n`, `--no-gpg-sign` or `-c commit.gpgsign=false`; a commit or `gh pr create\|edit` whose command, `-F`/`--body-file` file or heredoc carries AI attribution (`Co-Authored-By: Claude…`, "Generated with Claude Code", a `claude.ai/code` URL); `git push --force` / `-f` (not `--force-with-lease`); `rm` recursive and forced, any flag spelling, on a target outside the project (after `cd`); `k6 run` over 1000 VUs or 3600 s, on an origin outside `targets.allowlist` of `tests/perf/perf-onboarding.config.json`, against `production.origin` without `production.allowed: true`, or with no config; with `achilles-factory-rules.json`: a spend-listed spec, project or script without its per-segment opt-in (`spend.opt-in`), and a secret-shaped value written into a file in scope (`secrets.none`); a line over 32 KB naming `git`, `rm`, `k6`, `playwright` or `gh` | commit subject grammar ([commit-conventions](../../skills/achilles-orchestrator/references/commit-conventions.md)); a shell write to a pipeline state file (ledgers, journey map, cycle and coverage state, findings, quarantine); with the rule file: the verify stamp of `process.evidence` and shell writes into the `process.state` directory; rewrites a `playwright-cli` call with no, a reserved, a too-short or a too-long `-s=` slug to `-s=<role>-<hash of the agent id>` |
| 2 | Pipeline ledger model (`hooks/ledger.ts`) | Write/Edit of `tests/e2e/docs/onboarding-status.json`, `tests/perf/docs/perf-onboarding-status.json`, `.phase4-cycle-state.json`, `coverage-expansion-state.json` | nothing | schema validity (`claude-code/lib/validate.mjs`); transitions (a phase skip without a skipped phase and an authorised deviation, `approved` without a `handoverEnvelope`, a verdict change without `reviewerCycles` + 1, a third rejection that does not escalate, `runMode` without its `modeAuthorizer`); the deliverables of each phase it completes; an Edit that does not apply; the progress files losing a dispatched or returned entry; a ledger changed or deleted out of band since its last tool write (its hash is held in the session state). Separation of duties is the agents' write scope |
| 3 | Sign-off (`hooks/signoff.ts`) | tracker MCP transition and comment tools; `gh pr create\|ready` without `--draft` | any sign-off (a completing transition, a verdict-shaped comment, a published PR) while the ticket's evidence bundle holds a live credential in a HAR or `console.log`, named by field, value withheld | records the receipt `.achilles/adversarial-verification/<ticket>.json` from the JSON block a reviewer's report or hand-back carries; at sign-off, no receipt, a receipt not recorded by the adapter or changed since, one older than the newest spec, missing review fields (reviewer, `uiReviewed`, `coverageSufficient`, a zero score, a total at or below 12), no evidence bundle (`summary.md` plus a screenshot, video, trace or HAR, under an `evidence/` directory or `ACHILLES_EVIDENCE_DIR`), a degenerate ticket key; a PR binds to the branch |
| 4 | Dispatch discipline (`hooks/dispatch.ts`) | an expert spawned from the orchestrator's loop | nothing | prepends the preamble (brief path, report path, status words, the return schema the brief names); runs a background dispatch in the foreground; no brief or report path, a missing brief, a brief naming no skill for the role, a schema that is not the role's, a resumed reviewer, a second author while one runs, a dispatch ahead of a phase awaiting review, a fourth review round, a discovery-cycle inspector naming three sections |
| 5 | Return review (`hooks/returns.ts`) | an expert's turn end | nothing | one note to the orchestrator naming the gaps: no opening status word, no report at the dispatched path, a return that fails the schema its brief cited (Ajv in `claude-code/lib/validate.mjs`), a cited spill file that does not exist, an approval citing no or missing on-disk paths, a skill the brief named and the expert never loaded, the judge loop's consecutive improvements-needed count (status line; the third escalates). The return is never rewritten |
| 6 | Spec hygiene (`hooks/hygiene.ts`) | Write/Edit under `tests/`, root `playwright*.config.*`, `package.json` | nothing | test IDs on added cases (`claude-code/lib/test-id-scan.js`; `CIVITAS_TEST_ID_PATTERN`, else the rule file's `specs.shape.titleIdPattern`, else `TC` + area + 4-6 digits); the import boundary (`claude-code/lib/import-boundary-scan.js`); with the rule file: `specs.shape` intake and frozen directories, `selectors.no-inline`, `selectors.evidence`; the evidence floor of a diagnosing expert writing a spec or the page repository before reading a trace, screenshot, error context, video or reporter JSON; the journey map's line-1 sentinel and cycle state |
| 7 | Selector development (`hooks/selector.ts`) | Write/Edit of existing application source by an author on a selector brief; that author's Bash calls | an edit that is anything other than one added inert test attribute (the `.detected-convention`, else `data-testid`) on one opening tag (`claude-code/lib/selector-diff-validator.js`) | the eight steps observed and shown in the status line; an out-of-order step; a scope that ends between the patch and the visual diff gets the `git checkout --` line |
| 8 | Reporting and progress (`hooks/reporting.ts`, `hooks/progress.ts`) | after a Playwright run in Bash; a run loop's Write/Edit of a pipeline ledger or its `resume.json`; an expert's dispatch and turn end; the hand-back | nothing | keeps the run's stages, experts at work and finished experts in the status line, the pane and `.achilles/runs/<run-id>/progress.json`, and queues a progress prompt to the main session when a stage ends while stages remain (from a timer, never from the tool call); archives the run's artefacts to `.achilles/runs/<run-id>/` unless the reporter claimed them (`claude-code/lib/archive-run.mjs`, `ACHILLES_ARTIFACT_RETAIN` / `ACHILLES_ARTIFACT_MAX_MB`), naming skips, prunes and an incomplete copy; closes the expert's own `playwright-cli` sessions; the hand-back ends with a run summary line (experts by role, archives, an open judge loop or selector scope) |

Every deny names the action to take; where a skill section states the rule, the deny cites it.

## Switches and files

Switches the shipped code reads (the `opt-in-surfaces` lint compares this table against `claude-code/`, `bin/`, `scripts/` and `reporter/`):

| Switch | Effect |
|---|---|
| `ACHILLES_DISABLE=1` in the operator shell | the hook module passes every event through for new sessions (kill switch) |
| `ACHILLES_SKIP_CLAUDE_REGISTRATION=1` at install | the npm postinstall does not register the plugin with Claude Code |
| `ACHILLES_REQUIRE_CLAUDE=1` in CI | a missing `claude` CLI fails the registration step instead of logging the manual command |
| `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` at install | skip the Chromium fetch |
| `ACHILLES_SHOW_CONFIG=<path>` | the Playwright config `achilles-show` derives its headed, slow-motion run from |
| `FACTORY_RULES=<path>` | alternative location of `achilles-factory-rules.json` for the CLIs and the factory content rules |
| `CIVITAS_TEST_ID_PATTERN` | overrides the test-id shape the spec-hygiene scanner and `achilles-self-repair` use |
| `ACHILLES_REPORTER=off` | disables the Achilles Playwright reporter (`@civitas-cerebrum/achilles/reporter`) |
| `ACHILLES_ARTIFACT_RETAIN`, `ACHILLES_ARTIFACT_MAX_MB` | runs the reporter keeps under `.achilles/runs/` (default 5) and the trace/video size above which blobs are skipped (default 512) |
| `ACHILLES_REPORTER_SLOWEST`, `ACHILLES_REPORTER_SLOW_MS` | how many slowest tests the reporter lists (default 3) and the slow threshold (default 1000 ms) |
| `ACHILLES_HISTORY_RUNS`, `ACHILLES_HISTORY_DAYS`, `ACHILLES_HISTORY_MAX_ENTRIES` | the reporter's cross-run flakiness history retention |
| `achilles-factory-rules.json` at the project root | opts the project into the factory content rules (`selectors.no-inline`, `selectors.evidence`, `specs.shape`, `secrets.none`, `spend.opt-in`, `process.evidence`, `process.state`); no file, no rule |
| `SPEND_OPT_IN=1` as a leading assignment (the `optInEnv` of the rule file's `spend.opt-in`) | per-segment opt-in the Bash judge accepts for a spend-listed spec run |
| `ACHILLES_EVIDENCE_DIR` | extra directory the sign-off hook searches for evidence bundles |

State the adapter writes: `.achilles/` in the project (briefs, runs and their `progress.json`, summaries, self-repair run dirs, the sign-off receipts) and session state held by Claude Code (ledger integrity hashes, judge-loop counters, per-agent session slugs), which lasts one session. All of it is recreated; none of it is source.

## Limits worth knowing

- Role scopes bound tools and paths, not content: an author with `tests/**` can still write a bad test; the review dispatch is what catches that.
- The Bash judge reads one command line, quote-aware, one level of `sh -c` / `eval`. Aliases, functions, scripts and encoded paths are not seen.
- The sign-off receipt `.achilles/adversarial-verification/<ticket>.json` is recorded from the reviewers' reports by the adapter on the orchestrator's behalf (keyed on the reviewer agent id, so an author cannot forge it); a wrong reviewer verdict is still a wrong verdict. The sign-off hook resolves `.achilles/` from the session's git toplevel, not from a worktree, and compares the receipt's time with the newest spec, so a receipt written inside a worktree or before the last spec edit reads as missing or stale. `.achilles/` is gitignored; a committed receipt would arrive on CI with a rewritten timestamp.
- Run state lives in `.achilles/runs/<run-id>/` as `briefs/<slug>.md`, `reports/<slug>.md` and `resume.json`; the adapter's first message to the orchestrator names that directory.
- The import-boundary check is a static floor, not a sandbox.
- `pdftoppm` is optional; without it the reporting skill emits per-slide PNGs through Playwright for inspection.
