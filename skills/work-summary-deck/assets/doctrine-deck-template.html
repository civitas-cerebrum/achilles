Separation of Concerns

The Steps API removes selectors from tests. The page repository isolates them. Each layer changes independently.

Test Code
Business intent — what the user does
↓
Steps API
Interaction mechanics — how to click, wait, retry

Page Repository
Selectors — where each element lives in the DOM

When the frontend redesigns every selector, zero test files change. When the framework evolves, zero test files change.

ACT II — THE METHOD

Agentic Shift-Left

Four stages. A human starts it, agents do the heavy lifting, a human confirms the result, agents guard it going forward.

1
HUMAN

Triage

CX/revenue impact assessment. What matters enough to test? The one decision the methodology refuses to automate.

▶
2
AUTONOMOUS

Automate

Sub-agents discover, inspect, compose, and review. Dual-stage per journey. Schema-validated returns.

▶
3
HUMAN + HARNESS

Confirm

Adversarial review of the tests themselves. Negative control. Hook-enforced, not advisory.

▶
4
AUTONOMOUS

Gate / Heal

Gate the release; heal the suite. On failure: classify (app-bug, test-drift, flake), heal or quarantine, file evidence.

The Tests Get Tested

Two harness-enforced gates that block sign-off. Not best practices — physical enforcement.

⚖

Negative Control

Every test must be proven to fail where the fix is absent. A test that passes in both states proves nothing. The harness blocks QA sign-off until negative control evidence exists.

HOOK-ENFORCED
⚔

Adversarial Review

Before a ticket transitions to done, adversarial probes challenge the tests: false-positive paths, weak assertions, surviving mutations. The gate blocks until the review receipt exists and is newer than the newest spec edit.

HOOK-ENFORCED

The agent doesn't opt into the methodology. It has no path around it.

Enforcement, Not Instructions

The distinction between a methodology and a best-practices document is enforcement.

Gate Blocks Until

What This Enables

When the foundation, the lifecycle, and the enforcement work together.

  • ✓

    One sentence drives the entire QA process

    "Verify the checkout flow with evidence." The agent maps, composes, runs, collects evidence, proves the negative control, and files the report — gated at every stage.

  • ✓

    Test quality is not proportional to human attention

    Adversarial review and negative control mean a test that passes sign-off has been challenged and proven. The machine produces the proof; the human owns coverage — that every critical business flow is tested against every failure point with CX or revenue impact.

  • ✓

    Suites stay healthy

    The gate/heal cycle triages failures autonomously. App bugs get evidence. Test drift gets healed. Flakes get quarantined. The suite stays green and meaningful.

  • ✓

    Tests own their data — in a controllable environment

    A solid suite requires full control over test data: programmatically generate, update, and clear data and content, so every run starts from a known baseline and no test depends on the current state of content. The methodology is ready for that environment; the sandbox is the missing piece.

  • ✓

    The methodology travels with the package

    npm install is the onboarding. No wiki. No "we should update the testing guidelines." The methodology is code, and code ships.
