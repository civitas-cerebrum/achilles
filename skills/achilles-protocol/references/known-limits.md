# Known limits

One row per limit that ships. `Detector` is the case or lint that pins the behaviour. A change that closes a limit deletes its row. IDs are never reused; a gap means the row was retired or is pending a task in this release.

| KL-03 | `achilles-import-boundary-gate` is a static floor, not a sandbox: it parses the root `playwright*.config.ts`, the root `package.json` and every file written under `tests/`, and denies what it cannot read. `.d.ts` files with `export = require("../…")` or `import x = require("../…")` (type-only, but screened as code); `const { env } = process` and `globalThis.process.env.X` (write `process.env.X`); `arguments` inside an ordinary `function`. | `cases/86-import-boundary-gate.sh` §"import-boundary-gate: config indirection", §"the environment, the module wrapper and URL specifiers", §"Node builtins under tests/ come from an allowlist", §"loader aliases under tests/", §"the screen fails closed" | methodology |

| KL-15 | The Bash guards judge one command line's own words (`hooks/lib/shell-words.sh`), inverting to unrecognised = unsafe within it: a static floor. The commands inside a brace group, a function body, a `$( )` and a script a shell, `eval`, `env -S` or `npx -c` runs are judged where they are written. A command run under `env -C`/`--chdir`, `sudo -D`, `npx --prefix`, `git -C`/`--work-tree`, or `npm|pnpm|yarn|bun` with `-C`/`--dir`/`--cwd`/`--prefix` before `exec` (or `x`) has its relative operands judged under that directory. `$X` counts as a directory that cannot be resolved. Workspace selection (`-r`, `-w`, `--filter`, `yarn workspace[s]`) and a package-manager option before `exec` that the splitter does not know leave the directory unresolvable, which denies only the exec'd command's writes and a shell; any other program follows the unsafe rule below, so `pnpm -r exec tsc --noEmit` passes. A directory that is protected, inside protected state, above it or unresolvable counts as naming protected state. Git `rm`, `checkout`, `restore`, `clean`, `reset`, `mv`, `switch`, `read-tree`, `checkout-index`, `sparse-checkout` (unless `list` follows it) and `stash` (unless `list` or `show` is the first word after it) have one target set whatever their flags, `--cached`, `--staged`, `-n` and `drop` included: every operand (a new branch name of `-b`, `-B`, `-c`, `-C` or `--orphan` counts as one), plus the work tree when there is no operand, an operand does not resolve, an option is not one the guard knows, or the subcommand takes the whole tree (`stash`, `read-tree`, `sparse-checkout`, `checkout`/`switch` with `-f`, `--force` or `--discard-changes`, `checkout-index -a`, `reset --hard|--merge|--keep`). A short-option cluster ends at the subcommand's own value letter (`stash -m`, `restore -s`, `clean -e`, `checkout`/`switch` `-b`, `-B`, `-c`, `-C`); the rest is the value, and a letter outside the guard's git flag letters makes the work tree a target. `--pathspec-from-file` or a `:` pathspec also names protected state. The work tree is the `-C` directory for `clean`, `rm`, `mv` and `restore`; for the others it is the caller's directory unless `-C` is absolute. Git's `status`, `diff`, `log`, `show`, `ls-files`, `blame`, `stash list|show`, `sparse-checkout list`, `commit`, `add`, `rev-parse`, `grep` and `fetch` pass. On any git command, an option that makes git run a program or write a file (`--exec-path`, `--config-env`, `-O`, `--open-files-in-pager`, `--ext-diff`, `--textconv`, `--output`, `--upload-pack`, `--receive-pack`) denies the line whatever it names, and so does a global option before the subcommand that the guard does not know. `find` judges the command an `-exec`, `-execdir`, `-ok` or `-okdir` action runs as a command of its own; its start paths are write targets for `-delete` and for an action whose command is not a reader, and a reader given `rg --pre`, `file -C` or run from outside the system bin directories is not one. On the line itself `protected-artifact-bash-guard` treats every unrecognised option, program, sed command, wrapper option and git option as unsafe. An unrecognised wrapper option denies the line whatever it names; any other unsafe verdict denies only on a line that names protected state, and a directory above it does not name it, so `npx playwright test tests/e2e` and `git checkout <branch>` pass. `playwright-cli-isolation-guard` denies a command whose words, assignments, heredoc bodies or directory name `playwright-cli` in any letter case, and every command word that expands (`$x`, a glob, a backtick), unless the command is `playwright-cli` behind wrappers and options the splitter knows, a shell or `eval` whose only mention is its script, or a reader from the closed list in the guard header. **Not caught:** a target, program or config staged by an earlier call (a renamed binary, a program placed in a bin directory the guard counts as a system one but the user can write, such as `/usr/local/bin` or `/opt/homebrew/bin`, a `PATH`/alias/function/`git config`/`BASH_ENV` set in a previous tool call, a script file written earlier); a `cd`, `pushd` or `(cd …)` ahead of the command; `make -C` and `npm|pnpm|yarn … run`, which run a Makefile or package script staged earlier; a `docker run -v` bind mount; a registry package or other unknown program aimed at a directory above protected state (`pnpm dlx`, `yarn dlx`, `npx rimraf tests/e2e`), which follows the unsafe rule; branch and history operations that refuse to overwrite local changes (`git checkout <branch>`, `switch`, `reset <commit>` without `--hard|--merge|--keep`, `merge`, `pull`, `rebase`, `cherry-pick`, `revert`, `am`, `apply`, `worktree`); a whole-tree git operation run from a directory below the repository top, which is judged against that directory; a path or command built at run time (a variable assembled from parts such as `p=playwright; ${p}-cli`, `cd`, a symlink); text piped or fed into an interpreter or `xargs` at run time (`echo … \| sh`, `echo playwright-cli open \| xargs`, `xargs eval <<< …`, `source <(echo …)`, `base64 -d \| sh`, `source x`); a `BASH_ENV`/`ENV` file staged by an earlier call, even when the variable is set inline; a `{` program on `PATH` (judged as a brace group); a Unicode look-alike of a protected name (a different file). `ledger-integrity-chain` detects the resulting out-of-band ledger change. | `cases/92-protected-bash-fail-closed.sh`, `cases/02-cli-isolation-guard.sh` | Achilles hooks |

| KL-20 | `state-gate` judges one command line's own words (`hooks/lib/shell-words.sh`). Once a command names the state dir or the stamp or marker file name (as a component or a glob that could match it, case folded, with expansions read as empty or `/`, in a word, an `=` value, an `env -C`-style directory, or a word of a command string split again as the shell reads it; a shell's `-c` script, `eval` arguments and git message values are judged separately or inert) it treats every unrecognised command and every non-literal word as unsafe, counts a `cd`, `pushd` or `popd` it cannot resolve exactly as entering the dir for the rest of the line and an `env -C`-style directory it cannot resolve as running inside it, and passes only readers and provable copy-out ([factory-gates.md](factory-gates.md#process.state)). **Not caught:** a state path staged by an earlier call (a symlink, alias, function, variable, `cd`, `dotglob`, `extglob` or `CDPATH` from a previous Bash call); a name assembled at run time on a line that never names the directory (`D=.fac; rm ${D}tory/x`, `sh -c 'rm .fac$(echo t)ory/x'`); a whole-tree destroyer that names neither the directory nor the files (`rm -rf .`, `find . -delete`, `git clean -fdx`, `git stash -u`), on any line: it deletes the stamp, which fails closed at commit-gate (a) until a fresh verify, and the current-change marker, which turns the next commit after that verify into a maintenance commit that skips the evidence-trail check (b), and the change reviewer owns catching that; text fed into an interpreter or script that does not itself name the directory (`echo … \| sh`, `source x`, a script file); a config-borne program set by an earlier call (git `textconv`, `core.pager`). A read-only command outside the reader list is denied rather than judged (`sed -n`, `awk`): use `cat`, `head`, `grep`, `jq` or a listed `git` read. The gate assumes bash semantics; a shell with other glob or word rules (zsh alternation) is outside it. The commit gate's tree-hash check is no backstop: `hashCommand` is a repo script any agent can run, so a hand-written stamp can carry the current tree's hash, and state-gate is the only barrier against one. | `hooks/tests/cases/factory/state-gate.deny-cd-variable-then-rm.json`, `state-gate.deny-glob-star-in-dir-name.json` | Achilles hooks |
