# Known limits

One row per limit that ships. `Detector` is the case or lint that pins the behaviour. A change that closes a limit deletes its row. IDs are never reused; a gap means the row was retired or is pending a task in this release.

| ID | Limit | Detector | Owner |
|---|---|---|---|
| KL-01 | The kernel does not inspect the text of a dispatch brief; a dispatcher can pass anything it can read to a child. | kernel design (vendored) | kernel-mandate upstream |
| KL-02 | Roles that author and run code are contained by a static import/capability screen, not a sandbox. | `cases/kernel-mandate/07-write-then-execute.sh` | kernel-mandate upstream |
| KL-03 | `achilles-import-boundary-gate` is a static floor, not a sandbox: it parses the root `playwright*.config.ts`, the root `package.json` and every file written under `tests/`, and denies what it cannot read. Test code runs with full Node privileges; this screen is a static floor against accidental or careless reach into `src/`, not a sandbox. **Denied in the config:** an import outside the allowlist (`@playwright/test`, `@civitas-cerebrum/element-interactions`, `dotenv`, `dotenv/config`, `path`, `url`, bare or `node:`), any value-producing relative import, more than one export, an export that is not an object literal / `defineConfig` of them / a const bound to one and referenced nowhere else, a missing top-level `testDir`, any `globalSetup` / `globalTeardown` / `testDir` / `tsconfig` / file reporter outside `tests/`, `projects` other than an array of object literals, `Object.*` / `Reflect` / `Proxy` / `JSON` / `exports` / prototype access, another config extension. **Denied under `tests/`:** a relative specifier outside `tests/`, `#` and self-reference imports, any Node builtin outside the allowlist (`fs`, `fs/promises`, `path`, `url`, `os`, `crypto`, `util`, `buffer`, `stream`, `stream/promises`, `events`, `assert`, `assert/strict`, `timers`, `timers/promises`, `zlib`, `http`, `https`, `querystring`, `string_decoder`, `readline`, `perf_hooks`, plus `path/posix`, `path/win32`, `util/types`; bare or `node:`). Other bare packages are the kernel's codeImports. **Denied in both:** a URL-scheme specifier other than `node:` (`file:`, `data:`, `http:`; `https:` passes only under `tests/perf/**`, where k6 scenarios import jslib — Node itself never loads `https:`); a bare specifier with a `.` or `..` segment (`zz/../../src/app.js`, `https://../../src/app.js`, `lodash/../../src/app.js` resolve from `node_modules` and climb into the project) and any specifier containing `%` (the ESM resolver decodes `%2e%2e` to `..`); `eval`, `Function` (as a value), `createRequire`, `Reflect`, `arguments`; `process` / `module` / `globalThis` / `global` as values or through computed keys; any write to `process` state — assignment (including destructuring patterns, `for…of`/`for…in` targets), `+=`, `delete` — on `process.env.*`, `process.execPath` or any other `process`-rooted member, `process.env` passed on (`Object.assign(process.env, …)`, bound to a name), any reference to `process.execArgv` or `process.loadEnvFile`; `.require` / `._load` / `._compile` / `.constructor` / `.mainModule` / `.binding` / `._linkedBinding` / `.getBuiltinModule` / `.dlopen` / `.execve` / `.arguments` / `.caller` on any object, those names as destructuring keys or bare strings, and a computed key assembled from strings. **Not seen:** the runtime behaviour of allowed builtins (`fs.writeFileSync` or `fs.symlinkSync` creating a file the same or a later run loads, `http` fetching code), runtime writes under `tests/` by test code or by `npx playwright test > tests/e2e/x` redirects, config `webServer.command` (arbitrary shell), `use.launchOptions.executablePath`, the root tsconfig's `paths` (read by Playwright when the config names no `tsconfig`), `NODE_OPTIONS` in any env file dotenv reads (`.env`, or one under `tests/`, which passes as prose), a loader name reached through data the screen does not trace (a parameter, array element, property read or `.join` result used as a computed key), `.load(…)` on any object (every static route to a `Module` instance is denied instead), prototype pollution from code under `tests/` (runs after the config is resolved). **Known false positives:** `err.constructor.name` (use `err.name` or `instanceof`); `.d.ts` files with `export = require("../…")` or `import x = require("../…")` (type-only, but screened as code); `const { env } = process` and `globalThis.process.env.X` (write `process.env.X`); `arguments` inside an ordinary `function`. | `cases/86-import-boundary-gate.sh` §"config indirection", §"the environment, the module wrapper and URL specifiers", §"Node builtins under tests/ come from an allowlist", §"loader aliases under tests/", §"the screen fails closed" | methodology |
| KL-04 | The scaffolder is the only role that reads or writes `.env`. Its return reaches the orchestrator unvalidated (no schema mapping for `scaffolder-*`), and "never echo values" is methodology that nothing enforces. | `cases/85-qa-mandate-scopes.sh` §secrets-sweep-phase7 | methodology |
| KL-05 | The perf pipeline is not modelled in the QA mandate: under an active kernel `k6 run` and perf worker dispatches are refused. Run perf-onboarding with `KERNEL_MANDATE=0` until perf roles exist. | `cases/85-qa-mandate-scopes.sh` §"procedures the kernel refuses today" | methodology |
| KL-06 | No role may call tracker MCP tools, so ticket-driven-testing cannot post sign-offs under an active kernel. Remedy: add the tracker's tool glob (e.g. `mcp__atlassian__*`) to `roles.orchestrator.tools.allow` in the project's `.claude/kernel-mandate.json`. | `cases/85-qa-mandate-scopes.sh` §"procedures the kernel refuses today" | methodology |
| KL-07 | `repair-worker-*` dispatches and the contribution handover's `gh pr create` are refused under an active kernel; run `achilles-self-repair` and contribution handovers with `KERNEL_MANDATE=0`. | `cases/85-qa-mandate-scopes.sh` §"procedures the kernel refuses today" | methodology |
| KL-08 | `pr-attribution-gate`, `perf-load-safety-gate`, the MCP branches of `adversarial-verification-gate` and `evidence-bundle-gate`, and parts of `playwright-cli-isolation-guard` only act when the kernel is dormant: while it binds, the kernel refuses those commands first. | `cases/85-qa-mandate-scopes.sh` §"procedures the kernel refuses today" (orchestrator `gh pr create`) | Achilles hooks |
| KL-09 | `sync-kernel-mandate --check` without `$KERNEL_MANDATE_SRC` proves the vendored bytes match the lock, not that the lock matches upstream. | `cases/84-sync-kernel-mandate-check.sh` | Achilles maintainers |
| KL-10 | Kernel deny messages suggest `kernel-mandate explain`/`derive`; that CLI is not shipped by Achilles. | vendored text | kernel-mandate upstream |
| KL-11 | An existing project `.claude/kernel-mandate.json` is never overwritten; Achilles dispatches then bind to that manifest's roles. | `cases/71-achilles-kernel-activation-gate.sh` §postinstall | Achilles install |
| KL-12 | Several roles hold write scope on `onboarding-status.json`; who may record which transition is enforced by `onboarding-ledger-write-gate.sh`, not by the mandate; approval-class writes (verdict approvals, terminal status) must come from an approver `agent_type`, and a subagent write with no `agent_type` is denied. | `cases/51-onboarding-ledger-write-gate.sh` | Achilles hooks |
| KL-13 | The orchestrator may write anything under `tests/**`, including specs, fixtures and the page repository; delegating those to the scaffolder and composers is methodology, not enforcement. | `cases/71-achilles-kernel-activation-gate.sh` | methodology |

## Runtime requirements

| Requirement | Why | When missing |
|---|---|---|
| jq | every hook parses JSON with it | postinstall bundles one; hooks fall back to PATH |
| Node ≥ 20 | validator bundle, parser bundle, postinstall, CLIs | schema-validating hooks warn and allow; `achilles-import-boundary-gate` denies |
